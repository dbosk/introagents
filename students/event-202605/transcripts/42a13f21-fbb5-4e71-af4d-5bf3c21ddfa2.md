# KTH EECS Code of Honour Summary

## Core Principles

The code establishes that an academic atmosphere requires "mutual trust and confidence" with students and teachers pursuing knowledge through professional integrity. Professional integrity involves completing work in your own name, acknowledging contributions from others, understanding solutions, and accepting responsibility for quality.

## Student Expectations

Students must discover examination rules for each course component, including permitted aids and approved collaboration. The code states: "It is dishonest to use someone else's work (e.g., by copying text, figures, tables, or program code) when the student is expected to carry out the work independently."

Students should disclose what work is their own versus others'. Quoting and citing must be transparent. Using ready-made solutions requires disclosure. Seeking help when stuck is acceptable if openly reported.

## Teacher Expectations

Teachers should "provide clear instructions regarding which aids and forms of collaboration are permitted during examinations." They must create assignments that discourage plagiarism, align difficulty with learning outcomes, assess fairly, and respond constructively when students report shortcomings.

## Seven Key Rules

1. **Group responsibility**: All members are accountable for collective work

3. **Oral competency**: Present and defend your entire solution
4. **No copying**: Refrain from duplicating others' solutions
5. **Attendance integrity**: Manage attendance records correctly
6. **Proper assistance**: Provide help appropriately
7. **Generative AI**: Handle AI tools correctly

Violations involve using unauthorized aids or attempting deception during assessment. Teachers must report well-founded suspicion to KTH's disciplinary board.

## assistant — 2026-05-20T08:46:45.427Z

`chmod` ("change mode") sets file permissions on Unix.

**Syntax:** `chmod <mode> <file>`

**Two ways to write the mode:**

Symbolic — `chmod u+x script.sh` (give **u**ser e**x**ecute). Targets: `u` user, `g` group, `o` other, `a` all. Ops: `+` add, `-` remove, `=` set exactly. Perms: `r` read, `w` write, `x` execute.

Numeric (octal) — `chmod 755 script.sh`. Three digits = user/group/other. Each digit sums: `4` read + `2` write + `1` execute. So `755` = rwx for user, r-x for group and other; `644` = rw- / r-- / r--.

**Common ones:**
- `chmod +x file` — make executable
- `chmod 644 file` — typical for regular files
- `chmod 755 file` — typical for scripts/executables
- `chmod -R 755 dir/` — recursive

`ls -l` shows current permissions (`-rwxr-xr-x` etc.).
